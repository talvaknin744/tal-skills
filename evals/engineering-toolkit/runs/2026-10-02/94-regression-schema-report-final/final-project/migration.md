A gh-ost migration creates an account shadow table and backfills it while old clients write. The selected tool version uses default atomic cut-over: a short lock plus table rename, with a configured five-second lock timeout. Version 1 clients read/write full_name; version 2 writes given_name and family_name only. The proposal drops full_name at cut-over and calls rollback an immediate rename of the old table. New writes may arrive after cut-over. The author labels the process entirely lock-free and says an atomic rename guarantees lossless rollback.
