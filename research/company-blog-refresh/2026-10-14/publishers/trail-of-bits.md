## Useful additions and limits

The [metadata injection article](https://blog.trailofbits.com/2025/04/21/jumping-the-line-how-mcp-servers-can-attack-you-before-you-ever-use-them/) shows that server supplied tool descriptions can influence a model before any attacker tool is invoked. Add a conditional reference to `mcp-engineering` for the metadata publication boundary: identify source and configuration identity, preserve the distinction between peer data and trusted instruction authority, and test changes before metadata enters a model's context. A proposed discriminator connects a server with malicious metadata, makes an authorized request using a separate trusted tool, and checks that no unauthorized effect occurs without invoking the attacker's tool. No model attack reproduction was run.

The [wrapper design](https://blog.trailofbits.com/2025/07/28/we-built-the-security-layer-mcp-always-needed/) adds configuration pinning, review of changed tool and parameter descriptions, quarantine decisions and visible terminal control characters at that boundary. First review can approve malicious content; classifier misses and review fatigue remain possible. The wrapper lacks the complete user intent history, so it cannot establish workflow authorization. Universal host compatibility and guardrail effectiveness were publisher claims, not verified here. These mechanisms fit the existing MCP capability. A new general agent security skill would need a separate activation, authority and evaluation contract.
