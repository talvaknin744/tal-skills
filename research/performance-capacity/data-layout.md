# Data layout performance: applicability and correctness research

Research date: 2026-10-01. Scope: primary documentation and selected implementation excerpts relevant to the supplied Go/Python examples. The uploaded `Pasted text.txt` supplies hypotheses and code to inspect; its claimed speedups and universal rules are not evidence. No benchmark, hardware experiment, or concurrency test was run. This note distinguishes documented facts from requirements derived for a `data-layout-performance` skill.

## When this work is critical

**Derived applicability gate:** identify a service objective or explicit benchmark question, a measured hot path, its material contribution to CPU time, memory/GC cost, or contention, and the actual data/access pattern. Record fields touched per operation, working-set sizes, scan versus lookup behavior, read/write ownership, concurrency, and the ingestion/representation costs. Select a layout experiment only when those observations support a mechanism it could improve. A diagnosis or a finding that no change is justified is a valid outcome.

Treat column scans over large numeric batches, repeated traversal of pointer-heavy hot data, and demonstrated cache-line contention as candidate cases. Full-record access, small data already fitting cache, cold code, downstream waiting, or conversion costs that exceed scan savings are counterexamples to blanket SoA/padding advice. Kernel guidance explicitly cautions that false-sharing mitigation can increase space/TLB costs, move a hotspot, and fail to improve whole-workload performance. [Linux false-sharing guidance](https://docs.kernel.org/kernel-hacking/false-sharing.html)

**Derived acceptance gate:** preserve correctness and ownership first; then compare the same useful work on representative sizes/concurrency, including preparation where production pays for it. Require a worthwhile improvement at the service boundary as well as any kernel improvement. State measured effect, uncertainty, extra memory, maintenance cost, and environments where the conclusion does not apply. The pasted examples do not establish any such effect.

## Verified facts and their application

### Topology and PMU evidence

`lscpu` exposes CPU/cache-sharing/NUMA topology, but virtualized output can describe the guest or report inaccurate topology. Linux cache sysfs exposes cache level, size, shared CPUs, and coherency-line size. NUMA policy and CPU/memory placement are separate concerns; cpuset restrictions take precedence over memory policy. **Derived requirement:** capture the actual deployment architecture, allowed CPUs, limits, cache sharing, placement, and runtime concurrency before reasoning from a generic CPU diagram. [lscpu manual](https://man7.org/linux/man-pages/man1/lscpu.1.html), [cache sysfs ABI](https://www.kernel.org/doc/Documentation/ABI/testing/sysfs-devices-system-cpu), [NUMA policy](https://docs.kernel.org/admin-guide/mm/numa_memory_policy.html)

`perf stat` measures its selected command/scope; hardware events and hybrid PMUs require platform-specific interpretation. Events can be multiplexed, with enabled/running time used to estimate totals. Intel documents several causes of low IPC, including memory stalls, instruction starvation, branch misprediction, and long-latency instructions. Its exploration method drills down from the dominant bottleneck category at a hotspot. **Derived requirement:** do not classify a loop as memory-bound from low IPC plus a generic cache-miss count alone. Check event semantics, process/phase scope, PMU availability, multiplexing, and competing explanations; label unavailable evidence honestly. [perf stat](https://man7.org/linux/man-pages/man1/perf-stat.1.html), [perf_event_open read-format semantics](https://man7.org/linux/man-pages/man2/perf_event_open.2.html), [Intel IPC reference](https://www.intel.com/content/www/us/en/docs/vtune-profiler/user-guide/2023-0/cpu-metrics-reference.html), [Intel exploration method](https://www.intel.com/content/www/us/en/docs/vtune-profiler/user-guide/2026-0/general-exploration-analysis.html)

False sharing requires shared cache lines and at least one writer. `perf c2c` can identify contended lines using architecture-dependent sampling facilities; offsets, access sites, and ownership still need analysis. **Derived requirement:** distinguish different independently owned fields sharing a line from required communication through the same field. HITM/contention evidence alone does not establish false sharing. Padding cannot remove true sharing. [Linux false-sharing diagnosis](https://docs.kernel.org/kernel-hacking/false-sharing.html), [perf c2c](https://man7.org/linux/man-pages/man1/perf-c2c.1.html)

`cpu.CacheLinePad` is a compile-time architecture-specific padding type: the inspected x/sys source uses constants of 64 on x86 and 128 on arm64. It does not detect each host's cache-line size. **Derived requirement:** inspect actual field offsets, alignment, allocation placement, and array stride against target topology; evaluate space costs and actual contention before introducing padding. [CacheLinePad definition](https://raw.githubusercontent.com/golang/sys/v0.48.0/cpu/cpu.go), [x86 constant](https://raw.githubusercontent.com/golang/sys/v0.48.0/cpu/cpu_x86.go), [arm64 constant](https://raw.githubusercontent.com/golang/sys/v0.48.0/cpu/cpu_arm64.go)

### Layout, representation, and ownership

NumPy arrays combine a data buffer with dtype/shape/stride metadata. Basic indexing normally creates views; advanced indexing creates copies. Structured arrays model records with fields, offsets, and possible padding; individual fields can be strided views. **Derived requirement:** compare AoS, SoA, and hot/cold splitting against fields actually consumed, bytes touched, indexing behavior, and mutation/ownership requirements. Contiguous column access can improve a field scan, but these docs do not prove a universal layout winner or a particular speedup. [NumPy copies and views](https://numpy.org/doc/stable/user/basics.copies.html), [structured arrays](https://numpy.org/doc/stable/user/basics.rec.html)

`ascontiguousarray` can return an existing compatible contiguous array or allocate/coerce a new one. Contiguity does not imply exclusive ownership. `dot` semantics depend on dimensionality; incompatible dimensions fail, and BLAS is used where possible. Integer `sum` can overflow modularly without raising an error; floating summation behavior depends on dtype and reduction order. **Derived requirement:** specify dimensionality, equal column lengths, dtype/range/casting policy, aliases, empty input, NaN/Inf, zero denominator, and numeric equivalence before comparing implementations. Measure conversion/indexing allocations rather than promising a zero-copy path. [ascontiguousarray](https://numpy.org/doc/stable/reference/generated/numpy.ascontiguousarray.html), [dot](https://numpy.org/doc/stable/reference/generated/numpy.dot.html), [sum](https://numpy.org/doc/stable/reference/generated/numpy.sum.html)

Cython typed memoryviews enforce declared buffer representation and contiguity; read-only buffers require a compatible `const` declaration. Disabling bounds checks can turn invalid indexes into memory corruption or a crash; `nogil` does not establish exclusive ownership. **Derived requirement:** validate non-None buffers, compatible dimensions, lengths, dtype, strides, and index ranges at a checked boundary before entering an unchecked native loop. Use a fixed-width numeric contract where required rather than assuming native C `int` always matches an advertised format. `const` prevents writes through that view, not writes by other aliases. [Cython memoryviews](https://docs.cython.org/en/stable/src/userguide/memoryviews.html), [compiler directives](https://docs.cython.org/en/latest/src/userguide/source_files_and_compilation.html)

NumPy can release the GIL; shared mutation needs synchronization even in ordinary CPython. Free-threaded Python is an optional build, and extensions can re-enable the GIL; built-in container locks do not make compound application operations atomic. Shared memory supplies a buffer and lifecycle APIs, not a queue publication protocol. **Derived requirement:** document who writes each region, who can read it, how complete rows are published, when storage can be reused, and who closes/unlinks it. Check actual GIL/extension state. Account for unrelated-process resource trackers potentially unlinking shared memory when their owning process exits. [NumPy thread safety](https://numpy.org/doc/stable/reference/thread_safety.html), [Python free threading](https://docs.python.org/3/howto/free-threading-python.html), [shared memory](https://docs.python.org/3/library/multiprocessing.shared_memory.html)

Go atomic operations are sequentially consistent and can establish synchronization; ordinary payload accesses still require a happens-before argument. **Derived requirement:** for a ring, prove producer payload write before head publication and consumer read/clear before tail publication permits reuse. State single-producer/single-consumer ownership explicitly. Atomics and padding alone do not prove an MPMC queue, wait-free progress, or correct overwrite semantics. [sync/atomic](https://pkg.go.dev/sync/atomic@go1.27.1), [Go memory model](https://go.dev/ref/mem)

## Static audit of the pasted examples

These are deductions from the supplied source and the documented contracts, not observed runtime failures.

| Example | Correctness or measurement problem | Requirement for the skill |
| --- | --- | --- |
| Python `TickRing.vwap_last(m)` | The window is not bounded by retained capacity. With capacity 4, eight appends of prices 1 through 8 and unit sizes, requesting 8 rows gathers slots for prices 5–8 twice: 6.5 rather than the true last-eight average 4.5. Masking cannot recover overwritten history. | Track retained count; reject, explicitly clamp, or otherwise define requests beyond the available window. Define nonpositive/empty windows and zero-denominator behavior. |
| Its `np.arange(...); array[idx]` gathers | Index arrays allocate, and advanced-indexed price/size arrays are copies. The implementation is bounded in storage capacity, but query allocation/work scales with requested `m`. Concurrent append/query has no coherent-row snapshot protocol. | Include query allocation in the comparison. Consider split contiguous spans only if their semantics fit. Specify synchronization/snapshot ownership before claiming thread safety. [NumPy copies](https://numpy.org/doc/stable/user/basics.copies.html), [thread safety](https://numpy.org/doc/stable/reference/thread_safety.html) |
| Go SPSC `Pop` | It returns the value but leaves it in `buf[t & mask]`. If `T` contains pointers and the ring remains reachable, consumed objects remain reachable until overwritten. This is retention, not proof of a permanent leak. | If release is part of the contract, clear the slot before publishing tail. Validate constructor shift/capacity and prove index/counter-wrap invariants. Keep the SPSC restriction explicit. [Go GC reachability](https://go.dev/doc/gc-guide), [memory model](https://go.dev/ref/mem) |
| Go `SumNotionalSoA` | Iterating `Price` while indexing `Size` without equal-length validation can panic or silently ignore extra size rows. | Establish equal column lengths at a trusted boundary and define numerical/result semantics. |
| Cython `sum_notional` | The loop uses price length to index size with bounds checks disabled. A shorter size column can cause native out-of-bounds access. | Check shape/length before disabling checks. Check buffer/None/representation requirements; do not treat `nogil` as protection against concurrent writes. [Cython directives](https://docs.cython.org/en/latest/src/userguide/source_files_and_compilation.html) |
| NumPy conversion and shared-memory examples | Coercion may copy or narrow values; contiguity does not prove ownership. Sharing only the data buffer omits complete-row publication, reader synchronization, reuse, and lifecycle coordination. | Specify conversion/equivalence and shared-memory protocols, then include their costs. [ascontiguousarray](https://numpy.org/doc/stable/reference/generated/numpy.ascontiguousarray.html), [shared memory](https://docs.python.org/3/library/multiprocessing.shared_memory.html) |
| “Bounded ring/cache by default” | A work queue, overwrite history, and evicting cache have different contracts. Python bounded deques discard opposite-end items when appended at capacity. | Define capacity units, full/empty policy, ordering, ownership, rejection/overwrite/eviction accounting, and retry/backpressure behavior before picking storage. [deque behavior](https://docs.python.org/3/library/collections.html) |

## Measurement requirements and limits

Go introduced Swiss Table maps in 1.24; the inspected Go 1.27.1 implementation retains grouped Swiss Table lookup. Its 1024-slot table-capacity constant is an implementation detail, not a public latency bound or 1024-live-entry promise. `sync.Map` documents specialized workloads. **Derived requirement:** record the deployed toolchain, key distribution, lookup/update/miss ratio, growth, concurrency, and invariants; choose maps or indexed arrays from that workload rather than old runtime folklore. [Swiss Tables](https://go.dev/blog/swisstable), [Go 1.27.1 map source](https://raw.githubusercontent.com/golang/go/go1.27.1/src/internal/runtime/maps/map.go), [table source](https://raw.githubusercontent.com/golang/go/go1.27.1/src/internal/runtime/maps/table.go), [sync.Map](https://pkg.go.dev/sync@go1.27.1#Map)

Go's benchmark API provides timer boundaries and allocation reporting; `B.Loop` was introduced in 1.24. Benchstat reports medians/confidence intervals and recommends repeated samples. **Derived requirement:** predefine repetitions and interleave comparisons, preserve results against elimination, and measure both isolated kernels and production-paid preparation. `perf stat ... go test ...` also counts compilation/startup/harness work outside Go's timed loop; precompile and isolate the measured phase where possible, or label that broader scope. Statistical significance alone does not establish a worthwhile service improvement. [testing](https://pkg.go.dev/testing@go1.27.1), [benchstat](https://pkg.go.dev/golang.org/x/perf@v0.0.0-20260908200009-22c9c6c9d4da/cmd/benchstat), [perf stat](https://man7.org/linux/man-pages/man1/perf-stat.1.html)

Record scheduler concurrency, CPU placement/frequency conditions, versions, compiler options, working-set distribution, Python/NumPy/BLAS thread counts, allocation/retention, and whether warm/cold data matches production. Go's container-aware default `GOMAXPROCS` arrived in 1.25 and can update as limits change; verify actual values and overrides. Python benchmarking guidance also calls out system noise, affinity, and NUMA. **Derived limit:** a `ns/op` improvement does not establish p99 latency, useful throughput under load, or capacity headroom. [Go container-aware concurrency](https://go.dev/blog/container-aware-gomaxprocs), [pyperf system guidance](https://pyperf.readthedocs.io/en/latest/system.html)

Syntax-based suggestions such as “adjacent atomics imply padding,” “a dictionary/map loop implies SoA,” or “replace modulo with a mask” are hypotheses only. Require hot-path and ownership evidence plus equivalence proof; a bit mask additionally requires a valid power-of-two and compatible index/sign semantics. Avoid automatic application-wide layout rewrites from such heuristics. This restriction is a derived engineering judgment, not a language specification rule.
