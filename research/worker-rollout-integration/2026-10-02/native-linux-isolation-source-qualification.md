# Native Linux isolation: bounded source qualification

The additional official source evidence closes the specific child permission-inheritance and known file-handler questions left open by the earlier native02 review. I found no demonstrated enabled tool that bypasses the reviewed boundary. This is a separate evidence qualification for future grading; it does not rescore native02, declare the complete runtime registry known, or establish scenario acceptance.

The source audit is `tal-native-tool-registry-20261002-01`, pinned to official `rust-v0.159.2`, tree `ff6aec96948b70d94983af2641a6b67c94faeff5`. I independently recomputed SHA256 and Git blob SHA1 for all 54 files in the three manifests (33 initial, 13 child, 8 final-chain records). The manifests and official URLs are preserved here: [initial](history/native-isolation-source-audit/source-manifest.json), [child](history/native-isolation-source-audit/source-manifest-supplement.json), [session bridge](history/native-isolation-source-audit/source-manifest-supplement-2.json). Their identities and the raw audit/evidence hashes are in the accompanying JSON. Semantic review is bounded to the cited code paths, rather than a claim to have audited every line of those files.

The concrete source chain is:

- V2 spawn calls the shared preparation helper. It derives the child from the live parent configuration, applies role/model preferences, then reapplies the invoking turn's approval policy, cwd and permission-profile snapshot. [V2 spawn, lines 125–146](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/tools/handlers/multi_agents_v2/spawn.rs#L125); [child configuration, lines 51–84 and 170–193](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/agent/child_config.rs#L51).
- Role normalization admits selected model/instruction/preferences and disable-only feature/skill changes; it does not admit a role permission expansion. The installed native02 `tal-durability` role contains name, description and developer instructions only. [Role normalization, lines 69–128](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/agent/role.rs#L69).
- AgentControl captures the parent's ready environments and passes them into fresh and forked child creation. Execution-policy reuse is conditional on matching policy configuration; no runtime pointer identity is asserted. [Control, lines 577–619](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/agent/control.rs#L577); [fresh/fork transfer, lines 678–750 and 1218–1235](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/agent/control/spawn.rs#L678); [policy predicate, lines 183–200](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/exec_policy.rs#L183).
- Thread creation preserves those fields through the session arguments. Session construction copies the child permission state, uses inherited execution policy when provided or loads child-config rules with fatal failure on a load error, and passes the inherited environment snapshot into `Session::new`. [Thread manager, lines 1918–1948, 1995–2028 and 2256–2297](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/thread_manager.rs#L1918); [session startup, lines 602–636, 820–897 and 1110–1114](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/session/mod.rs#L602).
- Session environment construction uses the child defaults and inherited snapshot. Ready parent handles are reused, thread-owned configuration is refreshed from child defaults, and owner configuration is preserved. The cold-resume path separately rejects incompatible owner attachment/config/policy and intersects changed local permission requests with owner authority. [Session environment construction, lines 1430–1443](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/session/session.rs#L1430); [environment reuse, lines 209–232 and 272–325](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/environment_selection.rs#L209); [resume restrictions, lines 466–562](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/agent/control/spawn.rs#L466).
- Known model `apply_patch` verification/execution and `view_image` reads use the selected environment's sandbox context. The filesystem helper materializes the supplied policy, restricts networking and refuses an unavailable sandbox. These are source guards, not new model negative tests. [Patch verification, lines 348–365](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/tools/handlers/apply_patch.rs#L348); [patch execution, lines 87–112 and 169–197](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/tools/runtimes/apply_patch.rs#L87); [image reads, lines 159–177](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/core/src/tools/handlers/view_image.rs#L159); [filesystem helper, lines 100–168](https://github.com/openai/codex/blob/rust-v0.159.2/codex-rs/exec-server/src/fs_sandbox.rs#L100).

Task-path naming alone is not the role proof. That snapshot is active, not terminal review findings. All 13 native command probes passed, and all 120 baseline/final/actual file paths, hashes and modes match. Those probes test the command sandbox, not each model file handler or a child-specific negative case.

Effective-config observations disable web and external app/plugin/browser/computer/image/dependency capabilities and show no MCP servers. The named profile restricts tool access to the read-only trial and minimal runtime reads, denies other root/temp access, and disables tool networking. No dynamic tools were submitted by the audited launcher. These observations and the source chain support the known enforcement path. They do not supply a complete instantiated tool/extension inventory. The source's ability to accept extension contributors is not evidence that an unrestricted contributor was enabled; trusted frontend filesystem RPCs are likewise not demonstrated model tools.

The remaining inability is to enumerate the complete parent/child runtime tool and extension set or directly exercise every model-handler boundary. No concrete additional enabled unguarded surface was identified. For a stronger claim of exhaustive exposure/confinement, obtain supported resolved registry/executor provenance, or audit the complete instantiated extension wiring under the same configuration and check any additional enabled filesystem/network executor. A missing public `tools/list` endpoint alone does not justify a finding or partial credit. A future grader should apply the unchanged isolation criterion to its own sealed input/final inventory, observed operations and version-bound source/config evidence, while recording capability deviations and `case_compliant` separately. This qualification neither requires nor preassigns full credit.
