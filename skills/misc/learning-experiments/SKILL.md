# Learning experiments

Change one observable part of the learning process and test whether it improves the intended performance within the existing time budget.

## Workflow

1. **Observe a real episode.** Reuse a recent attempt, study record or description. Identify the target, current method, visible result, help and time. Separate observation from possible cause: omitting an endpoint is observed; rushing or misunderstanding is a hypothesis. Done when the bottleneck can be located in an actual task, or a small diagnostic is selected.
2. **Choose a relevant change.** Distinguish knowledge gaps, selection/execution problems, excessive input, task initiation, distraction and insufficient capacity. Read [experiment patterns](references/patterns.md) for the relevant branch. Select one change, the activity it replaces and the evidence that would support or reject it. Done when the experiment fits the existing appointment and retains necessary instruction.
3. **Run a bounded attempt.** Use the student's course or real-life task, a clear stop point and an output to inspect. Supply scaffolding when needed; record it. Capture only an observation useful to the decision. Done when the attempt or actual barrier is recorded, not when the learner agrees with an explanation.
4. **Evaluate later performance.** Compare a fresh delayed task of similar demand, with assistance and time visible. A subjective improvement can justify another trial but not a learning-effect claim. If task difficulty or conditions differ, qualify the comparison. Done when evidence supports keeping, modifying or dropping the change, or the result is explicitly inconclusive.
5. **Leave a restart cue.** Record the next concrete action and one unresolved question. Reuse the existing study log; keep reflection proportional to the session. Protect recovery and reschedule unfinished work visibly.

## Completion

Return a brief experiment card: **observation → possible cause → replacement action → time cost → fresh check → result/next decision**. If the user is starting a trial now, stop at the next learner action; leave later results pending.

Read [evidence boundaries](references/evidence.md) when attributing a technique or explaining a claimed mechanism. Select methods from the task and demonstrated performance, rather than assigning a fixed learning style or importing headline productivity multipliers.
